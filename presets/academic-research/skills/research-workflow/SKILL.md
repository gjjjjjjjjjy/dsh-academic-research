# 科研推进工作流

四种场景、两种交接物。**不是四个 Agent，也不是四个服务**——按当前会话需要，只做其中一段。

## 零、与设计规范的叫法对应

本技能按**场景**组织；[`docs/SUMMARY-SCHEMA.md`](../../docs/SUMMARY-SCHEMA.md) §0.1 按**工作方式**命名。
两套叫法并存，**不改名、不合并**，只标出各自指哪一段：

| Schema §0.1 工作方式 | 本技能 | 说明 |
|---|---|---|
| 研究整理 | 场景 1 · 研究梳理 | 同一件事 |
| 研究评议 | 场景 2 · 实验设计（受 §一 越位约束） | 技能把「评议」落在下一步实验卡上；**只有这一段**允许主动提出新解释、新实验与反证条件 |
| 实施推进 | 场景 3 · 科研实现 | 同一件事 |
| 恢复与交接 | §八 交接材料放哪（场景 4 只负责写复盘） | 技能当前**没有**独立的「恢复」场景；恢复执行时「核对真实代码与产物」的要求写在 §八 的三条边界里 |

## 一、谁的活

| 角色 | 做 | 不做 |
|---|---|---|
| 压缩模型 | 整理已有记录、保留原文、列出已有问题与明显缺项 | 新增科研结论、替用户选路线、编造证据 |
| 本技能（弱模型执行时） | 查找、摘录、整理、暴露缺口；把决定转成实施卡；把结果写成复盘 | 宣布「创新性不足 / 机制成立 / 值得投稿某期刊」；擅自扩大调参；擅自重跑实验 |
| 用户或高能力模型 | 判断研究路线、解释结果、确定对照与下一步 | 把尚未运行的方案当作已验证结论 |

**只有研究评议阶段才允许主动提出新解释、新实验与反证条件。** 其余几段不越位。

## 二、场景 1 · 研究梳理

把「我想改进这个方法」变成一个可以回答的问题。输出四段，缺项写 `缺口：—`：

```text
当前问题：究竟需要改善哪个现象？
已有依据：哪些论文、实验或代码行为说明这个问题存在？
现有解释：已经提出过哪些解释？哪些尚未检验？
关键缺口：还缺什么信息，导致目前不能决定下一步？
```

文献工作围绕**这个问题**展开，不输出「十篇相关论文」清单。每条保留：

```text
文献中的主张 → 使用的条件和证据 → 与当前项目的关系 → 尚不能直接迁移的部分
```

论文里没写清楚的内容标成缺口，不替它补全。检索与读文件用宿主已有工具；**没有这些能力时写明缺什么，不要在插件里假装已经完成检索**。

## 三、场景 2 · 实验设计

这一段由用户或高能力模型主导；技能负责把结论整理成**一张下一步实验卡**，而不是一份很长的研究路线图：

```text
研究问题：这次实验具体回答什么？
设计：采用什么方法、数据、对照和评价方式？
必须不变：哪些条件要固定，才能解释结果？
结果解释：
  出现什么观察会支持当前解释？
  出现什么观察会削弱它？
  什么情况仍然不能下结论？
执行边界：需要多少资源，什么条件下停止或返回决策？
```

两次实验指标不同、但方法和学习率都变了时：**列出两次配置与结果，指出条件不一致**，把「是否需要补对照、固定哪些变量」交给决策方。执行模型不得为了尽快得到更好的分数，自行把任务改成扩大调参。

## 四、场景 3 · 科研实现

把已确认的设计变成最小充分代码。执行前必须拿到：

```text
当前任务 + 相关规格和真实调用者 + 必须不变的科研定义 + 最小实施动作 + 验收方式
```

模板见 [`references/implementation-card.md`](references/implementation-card.md)。

普通工程细节（变量名、函数怎么拆）由执行模型处理；**研究口径、算法定义、产物含义不能让它临场猜测**。运行权限与审批复用宿主的工具管线——技能里写的「不要擅自跑昂贵实验」只是行为指令，**不是权限隔离**。

## 五、场景 4 · 实验复盘

每次阶段完成输出一个短复盘，不强行生成结论：

```text
实际做了什么：与原计划有哪些已知差异？
观察到了什么：指标、条件、日志和产物。
目前能说什么：已有判定及其依据。
目前不能说什么：尚缺对照、重复、来源或其他必要条件。
下一步：可以继续的动作，以及需要决策的问题。
```

**「没达到预期但排除了一个解释」是有价值的研究记录；「指标提高了但来源不清楚」不能写成已验证结论。**

## 六、两种交接物

| 交接物 | 用途 | 模板 |
|---|---|---|
| **决策包** | 需要用户或高能力模型判断时使用；**必须能脱离原会话阅读** | [`references/decision-packet.md`](references/decision-packet.md) |
| **实施卡** | 把已确认决定转成不需要猜的限定任务 | [`references/implementation-card.md`](references/implementation-card.md) |

**决策包不能只引用对方看不到的路径或 `S7:L1-L4`** —— 那些编号只在本次压缩内有效。判断必需的原文必须内联；文件路径作为出处保留，但不替代接收方实际需要读的内容。

决定返回后不要直接当成「已批准执行」。区分：

```text
提出方案 → 用户接受或符合事先授权 → 转成实施任务 → 实际执行 → 记录结果
```

只有改变研究目标、评价口径、重要产物行为或资源承诺时才走决策入口；普通工程修补不用每次询问用户。

## 七、与六节状态的关系

本技能产出**不另建台账**。新材料进入既有六节：

| 六节 | 承载 |
|---|---|
| `[goal]` | 当前研究问题、假设、判据、明确任务 |
| `[experiments]` | 计划、配置、执行进展、结果及产物 |
| `[evidence]` | 文献、实验、文件来源；支持与反证同时保留 |
| `[analysis]` | 已完成的研究评议、决策、理由与适用边界 |
| `[invariants]` | 关键原文、评价定义、配置与执行契约 |
| `[open]` | 待决策问题、已确认实施任务、阻塞与恢复动作 |

**阶段状态不得身份偷换**：`提出建议 → 确认方案 → 实现代码 → 运行实验 → 得到结果`。状态词只有五个 —— `建议 / 已确认 / 已实现 / 已验证 / 已否认`；升级状态必须写出依据（谁确认的、哪次验证、哪个产物）。`已实现`、`已提交`、`已验证` 是三件事，分别记录。

不要求每条普通回复都输出完整六节；完整格式只用于压缩、阶段交接或导出。

## 八、交接材料放哪

按项目既有习惯保存。没有既有习惯时可用最小结构：

```text
.research/
  STATE.md          当前六节状态，按需更新
  handoffs/Q3.md    一次决策交接及其答复
```

三条边界：

- **`STATE.md` 是交接视图，不是实时实验监控。** 恢复会话后，运行中的 job、工作树状态、产物是否存在，都要通过实际读取确认；没有查询能力时写「当前状态未确认」。
- **保存成文件 ≠ 可以安全删除旧证据。** 原文退出活跃上下文需要先有可回读的保存位置和明确的删除决定；这属于后续规格，**不由本技能自行淘汰**。
- **不做向量库、知识图谱、跨项目搜索。** 先证明一份状态文件和一份决策包确实让你少做重复解释。

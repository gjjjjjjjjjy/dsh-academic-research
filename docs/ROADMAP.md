# 扩展目标

包的最终目标是**一个完整的科研 agent**，而不是一个压缩器：它能承接研究问题、按已确认的方案
推进实施、把结果与产物对起来，并在换会话、换模型、改代码之后接着做下去。

**版本 0 只做了它的第一环——压缩后端**，因为交接不失真是后面一切的前提。下面的路径按依赖排序：
前两段让版本 0 真正可用，第三段把 agent 补完整。

版本 0 与同概念区其它包的区别只有一条：**只做压缩后端 + 附带的提示模板，不做科研工具**。
那是**这一版的范围**，不是最终目标。

## 已交付（版本 0）

- **压缩后端**：`ctx.compaction` 的唯一提供方。六节交接记录、来源引用逐字复制、
  跨压缩继续携带、V1–V4 校验 + 一次修复、`general` / `ml` / `optics` 三个领域包。
- **`research-workflow` 技能**：四种工作方式（研究整理 / 研究评议 / 实施推进 / 恢复与交接）
  的提示模板，附决策包与实施卡两个模板。**随包附带的提示模板，不是功能入口。**

版本 0 只解决一件事：**让交接不失真**。

## 后续开发计划

三段按依赖排序：前两段是第三段的前提。**长程科研工具是第三段，也是这个包最终想做的事**——
压缩后端只解决「接得住、不失真」，研究过程本身在操作层怎么做，需要工具。

### 阶段 1 — 让现有能力真正跑起来

- 接入正式 profile：**已完成**（web profile：tarball 安装、preset 的压缩 realm 内替换后端行、
  host 平面那一行已禁用；同一 realm 内始终只有一个 `ctx.compaction` 提供方）。
- 挂载 `research-workflow` 技能：**已完成**。技能放在预设目录内（`presets/academic-research/skills/`），
  预设的 `skill-filesystem` 行按 `baseUrl`（预设自己的目录）挂载它——**技能随预设一起被拷贝或从包内读取**，
  两种装法都带技能，不需要额外挂载步骤（与 dsh 自带 `cordis` 预设挂自己技能的做法一致）。
- 发布到 npm（包名不带 scope）：**未完成**——本机 `npm` 未登录（`ENEEDAUTH`），名字仍空着。
- 验收：**已完成**。六次真实 `/compact` 失败（均在修复前）：
  ① 593 秒：`chunkMessages: 40` 切成 4–5 块，某块的 `[invariants]` 写了逗号并列引用
  （`- S139:L2, S139:L7-L8`），旧解析器按「整行一个引用」判非法；② 13.4 秒：压缩调用转发了
  会话工具 schema，模型去调工具（V4）；③ 46.8 秒、④ 33.1 秒、⑤ 61.4 秒、⑥ 47.7 秒：都「缺少
  全部六节」——被拒输出分别是自拟格式的「会话整理」、DSML 文本工具调用、上一条助手消息原文。
- **根因**：区段取的是**较近的一段**，编号转录结尾就是正在进行的会话，模型顺着它继续任务，
  reasoning 一路吃满输出预算。离线复现（真实 system 提示词 + 真实尾部区段 + 真实模型）：
  旧请求形态 `finish_reason=length`、`reasoning=32698/32768`、**正文为空**。
- **修复与验证**：请求形态改为「任务与首行契约在最前 → `=====` 围栏区段 → 长契约」，并修掉
  DeepSeek 适配器把一条消息的多个 text 块 `join("")` 造成指令粘在区段末尾的问题。同一区段复跑：
  `finish=stop`、第一行 `## [goal]`、六节齐全。再用**真实模型 + 真实 `summarizeRegion`** 端到端
  跑一遍（`.localtest/repro-real.mjs`）：一次调用通过，程序逐字复制出 30 个保留片段。
- **真实会话验收通过**：一次 `/compact` 产出六节检查点（区段 `9–1977`、折叠 341828 tokens、
  `outputTokens 37690`），第二次在它之上折叠 `1992–2544`（152409 tokens、`outputTokens 23317`）。
  用会话日志按 `shadowedSeqs` 逐节点重建区段复核，两次各 11 项检查全过：本次定位的引用逐字一致、
  前次检查点的 27 个必保片段全部由程序逐字携带、携带片段没有嵌套包装。保留区跨压缩只增不减；
  自动触发按当前标定约需 700k token，成本高，`/compact` 是现实路径。
- 配置（按实测）：`recursive: false` + `chunkMessages: 160`（只在重新打开递归时生效）把
  N+1 次调用压成 1 次；`maxTokens: 32768 → 65536`，因为输出预算要和 reasoning 分——实测
  `input=142769` 那次 `out=24273` 里 20344 是 reasoning。

边界（本次有例外）：接入与挂载只改配置和文档；**引擎改动共六处，都是真实运行暴露的缺陷**：
① 提示词骨架在 `[analysis]` 下写 `(none)`，与 V1 要求 `decision:` 冲突，任何「本次没有决定」的
压缩都要白花一次修复调用；② `[invariants]` 的引用解析只认「一行一个引用」，模型写的逗号并列
形式会让整次压缩失败；③ 分块阶段把所有分块跑完才报错，失败时白付后面每次约 2 分钟的调用；
④ 压缩调用转发了会话的工具 schema，模型可以借此把这一轮变成工具调用而整次作废；
⑤ 请求形态让模型把区段当成待继续的对话——首行契约前置 + 围栏 + 分块间补分隔 + 修复引用上次输出；
⑥ 继续携带时把片段**内部**的空行也当成块间分隔一并丢弃，会静默改写跨轮携带的原文，而 V2 比对
的正是已被改写的片段，查不出来。六处均已修，并各补了回归测试；另外补了失败报文里的被拒输出
摘要（诊断，不是行为改动）。

### 阶段 2 — 工作流从「提示模板」变成可调用入口

现状：四种工作方式只有提示词，没有斜杠命令，也没有工具入口。这一阶段的目标是让它们
可以被显式调用，而不是只靠模型自己想起来。

- 入口形式（斜杠命令 / 工具 / 目录挂载）在**真实安装版本上确认后再定**，并同时更新本文档；
  在此之前文档里不写尚不存在的入口。
- 已知缺口：技能当前**没有独立的「恢复与交接」场景**（`恢复执行前先核对真实代码与产物` 的要求
  只写在 SKILL.md §八 的三条边界里）。四种**工作方式**与四种**场景**的两套叫法及对应关系见
  SKILL.md §零；做入口时一并决定这一段是否需要独立场景。
- 不为此新增运行时服务，也不做多 Agent 调度——四种工作方式仍由同一宿主会话承载。
- 验收：一个真实研究问题走完 `材料整理 → 强模型决策 → 小模型最小实现 → 记录结果 → 换会话继续`。

### 阶段 3 — 把科研 agent 补完整

前两段做完后，agent 能「接得住、问得清、做得下去」；缺的是**研究过程本身的操作能力**。
压缩后端负责把研究状态接住，这一阶段负责让研究过程本身可以被操作、核对和追溯——
这是把版本 0 的压缩后端补成一个完整科研 agent 的最后一段。

当前缺口：

| 科研 agent 缺口 | 当前状态 |
|---|---|
| 文献检索与引用溯源 | 无 |
| 附件（PDF 等）解析 | 无 |
| 实验设计与统计检查 | 无 |
| 可复现性核对（代码、配置、产物三者对应） | 无 |
| 跨会话科研记忆 | 复用宿主 `dsh-session-reference` 的有界只读快照，不另建存储 |

两条约束：

- **每项单独评估是否进本包**，并说明它与压缩后端的关系。任何一项都**不得塞进压缩引擎**，
  引擎继续只负责压缩。
- **不预先排定顺序，也不在没有真实需求时先造框架。** 先做哪一项由真实研究里先撞到的缺口决定；
  真撞到时再写具体的实施卡。

## 明确不做

**版本 0 不做，会随版本推进重新评估**（缺口见阶段 3）：

- 模型路由、多 Agent 调度、独立实验数据库、归档服务、跨会话记忆存储。
- 文献爬虫、实验调度平台、自动证据淘汰、知识图谱、自动自我修改规则。
  （文献爬虫是自建抓取基础设施，与阶段 3 的文献检索不是一件事；后者指接入已有的检索能力。）

**不随版本改变的设计约束**：

- 把采用 CC-BY-NC 类许可的第三方内容打包进本包：与本包 MIT 不兼容。四种工作方式的提示词
  自行编写。重新考虑条件：原许可方给出兼容许可，或改为「只桥接、不打包内容」的独立包。
- 第二个 `ctx.compaction` 提供方；再次 hook `agent/pre-step`。
- 把尚不存在的斜杠命令或工具入口写进文档。

## 已知限制：已接受，不用新机制解决

以下边界是当前设计的取舍，不是待修缺陷。**机制、后果与处置见 README「已知边界」**；
这里只记录"不新增什么"，以免后续把某一条当成缺口去补框架。

| 已接受的边界 | 明确不新增 |
|---|---|
| 保留区跨压缩单调增长，终需人工决定淘汰哪些片段 | 自动淘汰 / 归档系统 |
| 选择完整性不由程序保证（程序只保证被选中片段的复制准确） | 语义校验层 / 二次筛选模型 |
| V1 通过只说明格式合规，不构成执行授权 | 授权状态机 / 权限推断 |
| 工具结果裁剪器先于压缩器处理大工具结果 | 改裁剪策略；两者职责保持分开 |
| `maxTokens` 必须 ≥32768，构造时强制 | 自动降级 / 改小预算重试 |
| 自带预设是内置 `standard` 的整份拷贝（另加压缩后端与 `skills/` 两处改动），不随 dsh 升级更新 | 补丁语义（该层没有 patch 机制） |
| 效果绑定模型与配置（现有结果在 `deepseek-official / deepseek-flash` 上测得） | 据此宣称通用效果 |

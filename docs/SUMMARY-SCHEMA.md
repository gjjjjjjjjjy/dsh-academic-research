# dsh-academic-research 科研保真交接 Schema

版本：0
日期：2026-09-17
包名：`dsh-academic-research`
定位：**保真记录、问题交接、按已定方案执行；不让压缩模型代做科研决策。**

包的最终目标是**一个完整的科研 agent**；**版本 0 只实现了其中的压缩后端**，因此本文的
「已实现范围」严格以 §0.1 为准。版本 0 与同概念区其它包的区别只有一条：
**只做压缩后端 + 附带的提示模板，不做科研工具**——那是这一版的范围，不是最终目标。
扩展路径见 [`ROADMAP.md`](ROADMAP.md)。

包名表达的是**目标**（让长程学术研究不因压缩而断裂）。

本文是设计规范，不代表插件或 M1 源码已经实现、复审、运行或提交。

## 0. 职责与范围

### 0.1 三种职责，不要求三个 Agent

| 职责 | 应当做 | 不应当做 |
|---|---|---|
| 压缩模型 | 整理已有记录、保留原文、列出已有问题和明显缺项 | 新增科研结论、替用户选择路线、编造指标或证据 |
| 执行模型 | 根据明确方案做最小代码改动、运行指定实验、报告实际结果 | 擅改研究目标、评价指标、对照、数据划分或验收标准 |
| 决策模型 / 用户 | 判断研究路线、解释结果、确定对照和下一步 | 把尚未运行的方案当作已经验证的结论 |

**已实现范围**：本插件当前只实现压缩后端。代码执行发生在宿主的正常任务流程中，不发生在摘要调用里。

**范围升级（已确认，分阶段实施）**：产品目标从「保住上下文」升级为「让一个研究问题跨会话、跨模型、跨代码修改持续推进」——问题有依据，决策有记录，实施有边界，结果能追溯，下一步能接着做。四种工作方式：**研究整理**（读材料，整理已知事实、方法条件与信息缺口）、**研究评议**（分析可比性、替代解释、反证与下一步）、**实施推进**（按已确认决定做最小改动与必要验证）、**恢复与交接**（核对真实代码与产物状态，恢复未完成工作）。它们由同一宿主会话调用或手动切换模型完成，不要求多 Agent 调度。

**「连续性」指三件具体的事**，不是「记得上一轮聊过什么」：

| 连续性 | 要保住 | 失去它会出的问题 |
|---|---|---|
| 研究连续性 | 研究问题、已知证据、尚未解决的解释、下一步需要什么信息 | 换模型后重新讨论已经排除的方案 |
| 实验连续性 | 实验目的、设计、配置、实际进展、结果与产物的对应关系 | 把计划当结果、把最后权重当选中权重 |
| 执行连续性 | 已确认方案、不能改变的定义、工作树状态、最小下一步 | 代码和实验重新搭一套 |

**落地形态**：四种工作方式先由**一个 `research-workflow` 技能**承载（`presets/academic-research/skills/research-workflow/`，随预设一起分发，内含决策包与实施卡两个模板），**不新增斜杠命令、不新增运行时服务、不改压缩引擎**；技能产出直接进入既有六节，不建第二套台账。技能内部按**场景**组织（研究梳理 / 实验设计 / 科研实现 / 实验复盘），与本表的工作方式命名**两套并存**，对应关系见该技能的「§零」。技能是提示模板，因此「技能里写了不要擅自跑昂贵实验」只是行为指令，**不是权限隔离**——运行权限仍走宿主的工具与审批管线。

**版本 0 与压缩引擎的范围**。下面两类不要混：带「当前范围」的会随版本推进重新评估
（扩展路径见 [`ROADMAP.md`](ROADMAP.md)），带「设计约束」的不随版本改变。

- （当前范围）不新增模型路由、多 Agent 调度、独立实验数据库、归档服务，也不新建跨会话记忆存储。
- （当前范围）不把尚不存在的斜杠命令或工具入口写进文档；入口形式在实际安装版本上确定后再记录。
- （当前范围）不做文献爬虫、实验调度平台、知识图谱、自动自我修改规则，也不做按语义判断该淘汰什么的归档系统；携带集合只保留一种**机械**淘汰（§3）。
- （设计约束）**工作流模板不放进压缩引擎**：`AcademicResearchCompactionEngine` 继续只负责压缩。四种工作方式先由技能模板 + 宿主既有工具（文件读写、代码修改、终端、权限与审批）承载。
- （设计约束）**跨会话连续性走宿主已有的 `dsh-session-reference`**：它对被引用会话生成有界只读快照，并将其标为不可信上下文（禁止遵循其中的指令、权限声明与工具请求）。不另建快照格式，也不把快照当作当前机器状态的替代品——恢复执行仍须核对真实代码与产物。
- （设计约束）**压缩决策保持单一归属**：不得引入第二个 `ctx.compaction` 提供方，也不得再 hook `agent/pre-step`。
- （设计约束）**不引入采用 CC-BY-NC 类许可的第三方内容**。理由：这类许可是「署名 + **禁止商业使用**」，与本包 MIT 不兼容——把其提示词打进本包，等于授予读者一份原作者从未给出的商业许可，加 NOTICE 只能解决署名、解决不了 NC。四种工作方式的提示词**自行编写**。
  已有重新考虑条件：原许可方给出兼容许可，或改为「**只桥接、不打包内容**」的独立包（桥接件在运行时读取本机已有的安装，包内不含第三方内容）。

**高能力模型给出方案 ≠ 方案已经通过实验验证。** 审查意见也是建议，不自动覆盖已确认规格。与现有方案冲突时，把具体条款、调用者和反例交给用户或决策模型；不按审查者名气或模型强弱自动裁决。

### 0.2 优先级

原始记录保真 > 明确事实与判断的边界 > 可以继续执行 > 文本简短与好看。

优先压缩重复叙述，不压掉仍影响当前研究的结果、条件、失败和未决事项。不要求弱模型完成完整语义理解；校验仅对明确登记的字段和原文片段负责，不宣称任意会话完全无损。

**保真也包括执行语义：哪些对象参与、如何计算、产物代表哪个状态、什么情况下必须停止。** 这些规则记录在现有六节中，不新增一套契约 DSL、任务调度器或代码验证服务。摘要保住规则，不等于证明执行代码遵守规则；后者由实际 diff 和少量针对性运行验证。

## 1. 通用格式

### 1.1 六节固定

输出只有一份 Markdown 摘要，恰有以下六个二级标题，顺序固定：

```markdown
## [goal] 当前目标与假设
## [experiments] 实验台账
## [evidence] 记录与来源
## [analysis] 已有分析与判断边界
## [invariants] 精确保留区
## [open] 待决策问题与下一步
```

`[key]` 固定为 ASCII，不翻译；标题标签和叙述跟随会话语言。不得新增第七节。字段缺值写 `—`，无条目写 `(none)`；两者都不表示“已检查并确认不存在”。

既有 H/E 编号保持不变、不复用。仅给输入里确实存在的假设或实验编号，不为了填模板新增实验。递归分块时不得各自把不同实验重新编号为 E1。

已有检查点与新记录合并为一份。不同条件下的旧结果不能被新结果静默覆盖；明确纠正的记录标为“旧值 → 新值，纠正依据”。重复出现的说法不算新增证据。

### 1.2 不得自动补全的内容

没有记录时，不补造单位、不确定度、重复次数、baseline、Δ、显著性、路径、进度、因果解释或结论。

只有“准备运行”不能写“运行中”；有命令不能写“已执行”；进程结束不能写“假设已确认”。看见路径不等于已经读取文件，看见工具输出不等于科研结果已经独立核验。

### 1.3 来源引用：模型选来源，程序复制原文

原文保留不假定存在额外登记系统，也不由程序猜测哪些内容重要。**选择哪些内容重要，是模型或人的工作；把选中的原文准确复制出来，才是程序的工作。** 不能用「程序侧保真」这句话把前一件事假定为已经解决。

送入压缩模型前，程序为实际待压文本建立**本次压缩内有效**的来源编号与行号，同时保留原文：

```text
[S7]
L1: E3 使用 test-v2 进行评价。
L2: seed=42
L3: accuracy=81.3%
L4: checkpoint=/project/results/E3.pt
```

`S<n>` 与 `L<n>` 由程序分配。程序此时不知道这些内容是否重要，只知道每一行来自哪里。

压缩模型正常生成其余五节，但在 `[invariants]` 的草稿中**只返回引用，不重新拼写数值**：

```markdown
## [invariants] 精确保留区
- S7:L1-L4
```

**同一来源的多个行段可以写在同一行**，用逗号分隔（`- S12:L2, S12:L7-L8, S12:L20-L21`）；一行里除引用外不允许出现任何其它文字。程序逐个解析、逐个从原文逐字取出，合并「整行一个引用」的限制并不是保真要求——真实模型写过并列形式，按整行锚定解析会把整次压缩打死。

程序检查来源是否存在、行号是否有效，然后从原始文本逐字取出对应内容，替换草稿中的引用：

```markdown
## [invariants] 精确保留区
来源：S7:L1-L4（本次压缩定位）
原文：
E3 使用 test-v2 进行评价。
seed=42
accuracy=81.3%
checkpoint=/project/results/E3.pt
```

最终摘要必须包含原文，不能只留下 `S7:L1-L4`。该编号只在本次压缩中有效，不是假定存在的跨会话数据库地址。引用无效时使用 §4 的一次修复机会。

**携带过来的片段一律标为 `前次检查点（继续携带）`**，不沿用上一轮的压缩内定位标签。`S<n>:L<n>` 只在它自己那次压缩里有效，照抄既会把未被本轮选中的片段谎报成「本轮定位」，又会在下一次压缩里把包装套成两层、并逐轮累积。携带的是**原文本身**，不是上一轮的 `来源／原文` 包装。

**能保证什么、不能保证什么**：能保证被选中的片段不会在这次搬运中被模型改写；不能保证模型选中了所有重要片段，也不能保证原记录本身正确。例如模型只选了 `S7:L3`，程序可以准确复制 `accuracy=81.3%`，却不能仅凭这一行知道它属于 `E3`。因此提示词要求选择时包含实验归属和必要条件，但**「引用有效」不等于「实验归属已经得到语义验证」**。

同样，不能把模型选出的清单当作一份独立、完整的必保清单，再据此宣布「没有遗漏」。那只是证明「选中的东西都复制了」，没有证明「该选的都选了」。只有输入端本来就有一份独立指定的必保集合（例如上一份检查点中已经明确保留的原文），程序才有依据检查它们是否被继续携带。

### 3.1 机械淘汰：值被更晚记录取代的片段

携带集合原来只增不减，于是同一份检查点里会同时躺着 `Tests  31 passed (31)`、`Tests  33 passed (33)`、`Tests  34 passed (34)`，读者无从判断哪个是当前值。现在：**一个片段的所有行都是键值行，且每个键在检查点之后都出现了不同的新值**，该片段就不进入携带集合。

判据全部由程序执行，不含模型判断，也不改写原文：**淘汰只能整块进行**，逐行删改会毁掉「逐字保留」本身。

- 键值行的形状：`<键>=<标量>`、`<键>: <标量>`，或 `<键> <数字> <词…>`（`maxTokens: 65536`、`accuracy=81.3%`、`Tests  31 passed (31)`）。
- 不参与判据的：片段里任何一行不是键值行（源码、日志、JSON、散文）；值不是一个标量游程（`maxTokens: config.maxTokens,` 的逗号、`return 0;` 的分号）；多词值（`baseline: resnet50 on split-A`）；只有更早的记录、或更晚记录里是同一个值。
- `seed=42` 与 `seed=421` 是同一个键上的两个**不同**记录，不是新旧值（§4.1 已要求两者都在）；数字扩展因此不算取代。
- 淘汰**必须留痕**：被淘汰的片段以 `来源：前次检查点（已淘汰 · <键> 已有更新值）` 在当轮检查点里出现一次，原文照旧逐字，下一轮不再作为必保集合。没有留痕的丢弃就是静默删除原文。

这只解决「同一个槽的新旧值」这一种过期；源码、日志、JSON 与非键值片段仍然只增不减，超长会话最终仍由人工决定淘汰哪些（README「已知边界」）。

## 2. 六节内容契约

### 2.1 `[goal]` 当前目标与假设

这一节要让**没看过本会话的人先看懂项目在做什么、这一步推到哪了**，然后才是当前任务。开头两条固定字段（字段键 ASCII）：

```text
mainline: 项目主线——整体目标、当前处于主线的哪一步/哪个条目、该条目的验收标准。
progress: 本次推进——相对上一状态做了什么、到了哪一步、还差什么。
```

`mainline:` 以项目权威文件为准（如 `docs/MAINLINE.md`、`ARCHITECTURE.md`），**保留出处路径与所处条目编号**，只摘当前相关部分，不复制整份规范；原文没有就写 `—`。`progress:` 写成进展汇报而不是待办清单；本次没有推进就写 `—`。**两条都只写原文已有的内容**，不得据推测补全主线阶段或推进幅度。

保留当前研究问题、最新明确任务、交付物和用户的实现约束。不得只记录长远研究目标而漏掉当前要完成的代码或实验任务。

每条已有假设使用：

```text
H<n>：陈述；适用范围；支持/否定判据；状态；依据。
```

判据中的公式、阈值和单位逐字保留；未定义写 `—`。状态保留 `待验证 / 部分支持 / 被否定 / 已确认`，但**压缩模型不得自行升级状态**。原文已作判断而依据不足时，写“原文判断：……；依据：未溯源”，不代替原作者证明或否定它。

没有正式假设就写 `假设：(none)`。目标或判据是否需要修改，转入 `[open]`。

本项目的代码约束应持续保留：简洁易读、最小必要改动、优先沿用现有实现、不擅改实验口径、不为假设性需求增加框架或大量测试。

已有 MAINLINE、AGENTS.md 或用户指令中的当前适用条款应带出处保留；未提供正文时注明“据输入转述”。只摘实际相关条款，不复制整份规范。任务排除条件必须保留作用阶段，不把“不参与评价”外推为“不参与训练”。

### 2.2 `[experiments]` 实验台账：保留七字段

E 编号是记录标识，不占用字段。七个字段键固定为 ASCII，内容可使用会话语言：

| 键 | 标签 | 要求 |
|---|---|---|
| `purpose` | 目的 | 关联 H 编号或明确任务，说明实验要回答什么 |
| `design` | 设计 | 已确定的方法、数据与划分、对照及控制变量；保留各阶段的参与/排除集合和评价口径，未定部分显式写出 |
| `config` | 配置 | 本次实际使用或已确定将使用的关键参数，区分计划配置与实际配置 |
| `status` | 状态 | 计划 / 运行中 / 已完成 / 失败 / 中止；仅保留有记录的进展 |
| `result` | 结果 | 原始指标和条件；尚无结果写 `—`，不把预期结果填进来 |
| `artifacts` | 产物 | 精确路径及角色（选中模型/最后状态/续跑状态等）；已知 epoch、版本及下游读取者一并保留，不从名称猜测；区分预期与已产生 |
| `conclusion` | 结论 | 无判断写 `—`；有判断则标“原文报告已验证 / 推断 / 待判定”，并记录依据 |

结果不统一强制成 `value±err`。按记录实际形态保留：有 `±` 才保留 `±`，已有 SD/SE/CI 定义则一并保留；没有就写“不确定度未记录”，不能补成 `±0`。

baseline 和 Δ 已给出则原样保留；baseline 已给出但 Δ 未给出时，保留两边原值，写 `Δ=—（未计算）`。压缩调用不承担新计算；正常实验代码仍可按已确定公式计算指标。不清楚单位或是否可比时，保留原文并列为缺口，不自行解释。

失败原因、已完成阶段、日志、checkpoint、job id 或恢复命令，仅在原记录已有时保留。不把每次代码编辑独立登记为一个实验。

代码修复记录不自动变成一次成功实验。若修复改变标定、评价范围、聚合方式、选中权重或随机配置，已有结果是否需要重算应在 `[open]` 标明“已确定的影响”或“待确认”；既不默认旧结果全部作废，也不默认仍然有效。

### 2.3 `[evidence]` 记录与来源

沿用 `主张或记录 ← 来源`。正式来源仍只分三类：

- 文献：已有 citation key / DOI / arXiv id。
- 实验：已有 `E<n>`，指向台账中的记录。
- 文件：精确路径，附原记录提供的字段、行号或图号。

缺出处写 `← (未溯源)`，不得补造引用，也不在压缩时主动检索文献。

区分“工具输出记录”“用户报告”“模型意见”；它们是记录性质，不自动构成真实性评级。对话中给出的模型建议不能因附上 E 编号就变成实测事实。已有消息定位可作为记录的出处说明，但不冒充第四种科研证据。

重要结论的原始来源应随摘要保留，不能只剩“上次摘要说它是对的”。文件内容未提供时，只保留路径和可见描述，不假装读过文件。

### 2.4 `[analysis]` 已有分析与判断边界

本节是**已有分析的交接区，不是压缩模型的自由推理区**。

使用两个槽位。字段键保持 ASCII —— 机器判定不依赖会话语言，字段周围的叙述跟随语言：

```text
decision:  已提出的行动方案及其当前决策状态，包括尚未确认的建议。
state:     建议 / 已确认 / 已实现 / 已验证 / 已否认（§2.7）。
basis:     该状态的依据；没有来源写 —。
question:  状态为「建议」时必填，指向 [open] 中存在的 Q<n>。
judgement: 解释、分析、推断及其依据，含已有疑点。
```

没有决定时写一行 `decision: (none)`；该空项不要求 `state:` 与 `basis:`，也不要求模型编一条决定出来。

**出现在 `decision:` 里不等于已经获准执行。** 建议只有在后续输入给出确认依据后才能升级状态，并把动作放入 `[open]` 的 `已确定下一步：`。强模型提出过、或被重复写过几次，都不构成升级理由。

有明确记录时保留跨实验关系并点名 E 编号；没有时不强制寻找矛盾、不强制排除替代解释、不强制生成反证条件。

同一指标出现不同数值但实验条件是否一致未知时，只写“记录存在差异，可比性未定”，不直接宣布相互矛盾。

已有“已验证 / 推断 / 猜测”标记原样保留；不要求三层都有内容，不让压缩模型给已有判断重新评级。允许写“推断性结论”，禁止把推断升级成已验证事实。

高能力模型或用户的已有决策写成 `decision:` 条目并把 `state:` 标为 `已确认`，保留决定、理由摘要和已知出处；执行上的下一步放入 `[open]`。压缩模型不自行声称已经获得高能力模型审核。

已审查但未采纳的建议，保留“不改的理由”，并把当前执行限制放入 `[open]`。不能在下一次压缩中把“审查建议”改写成“必须修复”，也不能因暂时不支持某分支而补造该分支的实际调用者。

### 2.5 `[invariants]` 精确保留区

保留影响当前实验解释、复现或恢复执行的原文片段，包括：

- 指标、baseline、已记录的 Δ、不确定度、重复次数及其对应实验和条件。
- 公式、单位、阈值、常量与定义。
- 关键配置、代码/数据/模型版本、seed 与确定性设置。
- 配置、结果、checkpoint、日志、原始数据的精确路径；必要的报错和恢复命令。

**优先保留带上下文的原始行或小段，不只摘出裸数字。** 数值必须仍能对应到原实验、指标和条件。禁止四舍五入、单位换算、符号替换、公式化简和路径改写。

原文保留采用「模型选择来源，程序复制原文」的方式（§1.3），不假定存在额外登记系统。每次压缩前，程序为待压文本建立本次有效的来源编号与行范围映射。压缩模型在 `[invariants]` 草稿中返回需要保留的来源范围；程序检查引用有效性，从输入中逐字取出对应片段，填入最终摘要。原文片段应包含实验归属、指标和必要条件，不能只选裸数字。前次检查点中需要继续携带的明确保留片段，可直接复制；当前区段中新片段的选择仍由模型完成。

新引用若已被某个携带片段按**整行边界**覆盖，就不重复搬运；判定**不得用子串包含**——`seed=421` 含有 `seed=42`，按子串判定会把一个新值静默丢弃，而被丢弃的引用不会进入已解析集合，V2 也就无从发现它，摘要会带着缺值被接受。程序保证选中片段的复制准确性，不宣称选择完整、事实正确或科研语义已经验证。没有独立必保清单时，不得报告「所有关键数据均已保留」。

可以只用一次调用内的原文片段清单，不引入数据库、完整对象图或额外持久化格式。自动识别不明确时保留稍多上下文，不靠复杂启发式假装理解全部科研语义。

保留区不是全部日志的副本。重复中间输出可以压缩；但仍被分析、调试或下一步决策引用的记录不得删除。不能以“路径还在”替代从未实际保存过的原始内容。

当前任务已有以下**执行契约**时，同样保留其原文与适用范围；无关项不展开，不凭模板补全：

- 范围与顺序：训练/开发/评价各用哪些任务，排除哪些；评价臂固定顺序及 baseline 的明确身份。
- 计算定义：目标函数、阈值比较符、平局规则；聚合对象、权重、分母与去重规则；对照差的方向。
- 产物身份：产物名或路径对应选中 epoch、最后 epoch 还是续跑状态；下游实际读取哪个产物。
- 执行边界：实际进程分工、共享文件的写入者与同步条件；缺关键数据、状态不一致时的既定停止规则；seed 的角色和已要求的约束。

只保留已有定义，不新增统一配置系统。特别是缺少目标函数、比较符或平局定义时，把算法问题交给决策方，不允许仅凭一个失败样例拼补候选点后宣布算法正确。

### 2.6 `[open]` 待决策问题与下一步

按需要记录四类内容，不强制每类都有条目：

1. 已确定、可以执行的下一步：目标、最小实施动作、必须不变的条件和验收方式。
2. 待决策问题：交给用户或高能力模型，不由压缩模型代答。
3. 阻塞项：明确缺少的数据、权限、算力、接口或参数。
4. 已否决方案：方案、原有否决理由、已有重启条件；不能编造永久禁止条件。

待决策问题使用以下紧凑数据包：

```text
Q<n> · 问题：究竟需要决定什么？
依据与缺口：相关 E 编号、关键原值或精确保留区位置；缺少哪些信息。
需要的答复：例如确定对照、解释差异、选择下一步实验；不预设正确答案。
执行边界：哪些既定任务仍可继续，哪一步需要等该问题解决；原文未定则写 —。
```

无需凑够固定数量的问题，也不要求模型提供候选方案、优先级评分或推荐答案。可以根据显式缺字段、执行报错、要求冲突或用户已有疑问形成问题；不得制造“有深度”的问题。

问题获答后记录决定及出处，把明确动作转入可执行项。只有涉及科研有效性或改变既定方案的歧义才需要升级决策；普通命名、函数拆分等工程细节由执行模型按简洁原则处理。

代码修改期间，再用普通条目交接以下实际状态；这些条目是 §2.7 状态词升级所需的依据来源，不新增第八个实验字段：

```text
工作树：是否未提交；基准 commit、修改文件及 diff 定位有记录则保留，否则 —。
处理：哪些条目报告已改、已删或未采纳；谁报告的。
验证：实际运行过的命令、观察结果与未覆盖项；未提供证据不等于“没有验证过”。
产物影响：哪些既有结果/模型需重算或复核；没有决定则列为待决策。
```

**报告已修 ≠ 已查看当前 diff ≠ 回归通过 ≠ 正式重跑完成；提交状态另行记录。** 不把工作树改动归到旧 commit，也不因交接需要擅自提交、覆盖产物或重跑昂贵实验。被拒绝的修法，按“建议 → 未采纳原因 → 当前处理 → 已有重新考虑条件”保留；没有新依据时不重复尝试。

### 2.7 阶段状态词表：不新增状态机，但要能区分建议与已验证

同一内容会经历 `提出建议 → 确认方案 → 实现代码 → 运行实验 → 得到结果`。这些阶段**可以变化，但不得发生身份偷换**：把建议写成已确认、把已实现写成已验证，是交接失效的首要原因，也正是 §0.1 验收重点要拦住的东西。

要求：`[analysis]` 中记录的决定、`[open]` 中的已确定动作与已否决方案，各自带一个状态词，取值**仅有五个**。`Q<n>` 待决策项**不需要**状态词——它本身就是「尚未决定」的记录格式（§2.6）：

| 状态词 | 含义 | 升级所需的记录 |
|---|---|---|
| `建议` | 有人提出，尚未被确认 | 提出者与出处 |
| `已确认` | 用户或决策模型已明确同意执行 | 谁确认的、在哪条记录里 |
| `已实现` | 代码或配置已按确认方案改完 | 改了哪些位置；**不等于已提交，也不等于已运行** |
| `已验证` | 已有实际观察支持它成立 | 哪次运行、哪个产物、哪次读取；**不认「报告已修」** |
| `已否认` | 已明确不采纳，或被实验否定 | 否决理由与已有重启条件 |

规则：

- **升级只认记录，不认语气。** 没有写出依据时不得升级状态，保持原状态并写 `依据：—`。
- `已确认` 只能由用户或决策模型的明确表述产生，压缩模型不得自行认定。
- `已实现`、`已提交`、`已验证` 是三件事，分别记录；工作树未提交时，`已实现` 条目必须同时保留未提交状态。
- 既有产物是否受某次改动影响，属于 `[open]` 的待决策项，不得写成 `已验证`。
- 研究评议产生的新判断作为**新条目**加入 `[analysis]`，不得回头修改已被逐字复制的原始结果（§1.3）。

**这不是状态机。** 不定义转移、不自动推进、不新增校验引擎；它只是五个词的封闭取值，加一条「升级须凭证据」的记录规则。

**落地形态（已实现）**：状态只挂在 `[analysis]` 的**非空 `decision:` 条目**上；解释留在 `judgement:`，不带这套状态；`[open]` 保留 `已确定下一步：`、`Q<n>`、`已否决方案：`，**不重复维护决策状态**。也不得把这五个词套到 `[experiments].status` 或 `conclusion` 上——实验是否运行、方案是否确认、结论是否验证，是三件不同的事。

V1 只做三项检查：

1. `[analysis]` 必须出现 `decision:`；没有决定时写 `decision: (none)`，该空项豁免 `state:`/`basis:`，也不要求模型编造一条决定。
2. 每条非空 `decision:` 必须带 `state:`（五词之一）与 `basis:`；`basis:` 无来源时允许 `—`。
3. `state: 建议` 的条目必须用 `question:` 指向 `[open]` 中存在的 `Q<n>`。

不加状态转换引擎；V1 不判断「依据足不足」，也不扫描全文猜测哪里藏着未登记的决定。检查只作用于新生成的结构化条目，**不作用于 `[invariants]` 携带的原文**。

**V1 通过只说明记录符合格式**：不说明状态与原始证据一致，更不构成执行授权。`basis: 用户已确认` 是模型的记录，不是程序核实过的用户确认。

## 3. 保留与压缩规则

**不使用“最近 N 条”作为删除研究状态的唯一依据。** 以下仍与当前任务有关的内容必须保留：运行中实验、尚未完成的已确定计划、当前 baseline、支撑或反驳当前假设的关键实验、未解决失败、阻塞及待决策问题。

重复讨论、未采纳的泛泛设想、没有继续用途的过程叙述可以合并。历史结果不再详细展开时，仍保留当前研究需要的关键值、条件与来源。不新增归档服务，也不声称不存在的完整台账会兜底。

不能既承诺无限保留历史，又承诺摘要永远固定很短。必留内容超过预算时报告预算不足，不悄悄删除关键数据。

## 4. 自动压缩与最小校验

### 4.1 线性流程

```text
取得待压区段和已有检查点
→ 程序为待压文本建立本次来源编号与行号
→ 生成六节摘要（[invariants] 只写来源引用）
→ 程序校验引用有效性，逐字取出原文
→ 并入前次检查点中需继续携带的保留片段（值已被更晚记录取代的按 §3.1 淘汰并留痕）
→ 四项检查
→ 失败时携缺项修复一次
→ 通过则返回；仍失败则报错，不提交失败摘要
```

沿用现有后端的自动触发、保留窗口和 token 预算，不在本插件重建调度器。递归分块仅在现有后端需要时使用；各块产出的来源引用按本次编号解析成原文后，继续传递到合并阶段，不只保留一层模型转述。

### 4.2 四项检查，限定可检查的范围

| 检查 | 最小实现范围 |
|---|---|
| V1 结构 | 六个键完整、唯一、顺序正确；`[goal]` 带 `mainline:` 与 `progress:` 标签；实验具有七字段；没有用空白替代约定缺值标记；`[invariants]` 草稿只含来源引用；`[analysis]` 的 `decision:` 条目按 §2.7 三条检查（标签与空项豁免、`state:` 枚举与 `basis:`、`建议` 的 `question:` 指向存在的 Q） |
| V2 原文 | 独立必保集合（前次检查点已明确保留的原文）逐字出现在最终摘要中；本次模型选中的引用全部可解析，解析出的原文逐字出现在最终摘要中 |
| V3 数值绑定 | 整段除数字、单位与标点外**没有任何文字**的切片判失败并要求扩大范围。判据只看有没有字母（任意文字系统），不看是否命中已知词表 |
| V4 截断 | 模型接口报告截断、**改用工具调用**、返回空内容或明显不完整时，不能当成成功摘要 |

**保证范围（必须与机制一起说明）**：V2 证明的是「被选中的片段按原文复制成功」。它不证明选择完整，不证明原记录本身正确，也不证明「该选的都选了」。只有存在独立必保集合时——即前次检查点中已明确保留的原文——程序才有依据检查它是否被继续携带；不存在独立必保集合时，不得报告「所有关键数据均已保留」。V3 只拦截明显缺少上下文的裸数字选取：**整段除数字、单位与标点外没有任何文字**才判失败，与是否命中某个词表无关。它不证明片段的科研含义，也不验证该范围在语义上确实属于某个 E。**没有匹配到已知词法锚点，本身不应被当作语义缺失的充分证据**——判据是必要条件而非充分条件；尤其纯中文的决定和约束不一定带文件名或代码标识符，因此不把词法锚点做成不断增长的指标白名单。反引号只是格式，不自动构成上下文：`` `81.3` `` 仍是裸数字。程序不判断哪些原文重要，那一步仍由模型完成。

V2/V3 不只检查“数字是否在某处出现”，也不声称能识别所有隐含的语义错误。原文按引用逐字复制，少做复杂解析。新增的执行契约复用 V2 的原文携带机制，不增加代码扫描、自动因果判断或新的 V5/V6 校验引擎。

缺失清单包括实验/字段、原值或原文、问题类型；将清单交给模型修复一次即可。不自动改数值、不回退普通摘要、不多轮自我修复。

不新增生产环境跳过保真校验的开关。宿主如何处理报错由集成约定负责；本 Schema 只要求失败摘要不被提交，不为此另建一套运行时。

## 5. 领域包

保留 `domain: general | ml | optics`，不新增领域包或插件依赖。

领域包仅补充当前工作实际需要的配置和原文保留提示；不要求弱模型进行领域诊断，不机械展开所有可能字段。

- `general`：关键参数、样本/输入、评价方式和产物。
- `ml`：模型与权重、数据版本与划分、关键训练参数、精度、seed、评测定义；资源或 tokenizer/processor 信息影响当前工作时保留。
- `optics`：波长、偏振、几何/材料和测量或仿真条件；涉及相机、标定、不确定度时保留其已有记录，不自行计算误差合成。

领域相关但尚未明确的问题可列入 `[open]`；不把“需要知道这个量”当成“已经知道这个量”。`domainExtra` 只追加确有需要的提示，不覆盖基础保真规则。

## 6. 轻量实现约束

### 6.1 压缩引擎：仍只做压缩

范围升级不改变这条边界：`ContinuityCompactionEngine` 只负责压缩，四种工作方式不借压缩调用执行（§0.1）。

优先在现有压缩后端上改提示词和少量校验。默认只需要入口/流程、提示词、校验三个职责；可按现有工程合并或拆分，不设行数 KPI。

不新增通用 Agent 框架、模型路由器、复杂状态类、事件总线、持久化台账、自动科研评分或一套可配置校验引擎。不为了假设性扩展引入抽象层。

只在真实边界做必要检查：模型输出、文件/配置读取、关键数据是否缺失。内部明确的数据不逐层重复兜底；异常不要捕获后用假默认值继续。

科研代码允许把已确定参数集中写在脚本顶部。既有参数来源仍应沿用，未经授权不擅改。优先直白函数和最小依赖，注释解释实验口径与实现理由，不逐行复述代码。

最小测试集中在一个文件，覆盖少量关键用例：

- 一个中文或英文六节摘要可通过；另一语言可作为同一用例的输入变体。
- 漏字段、空节留白、把数值直接写进保留区（而非给引用）会失败。
- **误引或互换实验结果不在此列**：程序只保证被选中片段的复制准确性，无法发现范围指错（§4.2 保证范围）。
- 计划实验不会被填上不存在的结果；无不确定度时不会要求生成 `±0`（可用固定样本回归检查）。
- 第一次失败只修复一次；持续失败或截断不会提交。
- §2.7 的三项：空项豁免、`state:` 枚举与 `basis:` 必填、`建议` 的 `question:` 指向存在的 Q（表驱动）。

提示词对真实模型的约束不能仅靠固定样本证明；用一份脱敏科研会话做小规模人工抽查即可起步，不把这阶段扩大成庞大的模型评测工程。不追求覆盖率数字、巨量边界测试或复杂 mock。

### 6.2 执行模型：最小改动，不省略真实正确性条件

写代码前，仅就将修改的部分确认“规格原文 → 实际调用点 → 最小反例/验收观察”。正常命名和局部结构自行处理；规格冲突、优化目标、聚合口径或模型选优含义不明时，先带相关代码片段提问，不猜。

同一概念沿用同一份定义：任务集合、臂顺序、baseline 身份、选中 epoch 和产物出口，不在不同函数中另写略有差异的副本。已有配置为唯一来源时继续使用它；不为统一而新建配置平台。

“少防御性编程”不删真实约束：缺必要组不能静默跳过；已要求的 seed/臂序约束在昂贵运行前检查；两个进程实际共享文件时必须处理写入归属和完整发布。原子发布只解决半文件，不替代进程身份与真实同步。不要为不存在的调用者增加支持分支，不新增无限重试、自动修复或静默回退。

真实故障的验证优先用小输入或短运行，按实际修改选择，不给所有任务强制分配测试数量：数值/排序问题用微型反例；评价范围和聚合用能看清成员、权重与分母的小输入；产物选择沿真实下游入口回读；并发问题做短的双 worker 冒烟。昂贵训练不能替代这些检查，单次冒烟也不能证明不存在并发故障。

测试服务已知反例与当前调用链，不建设大规模兼容矩阵。删除死分支、重复存储、整份大对象打印；保留复现所需的精简配置、seed、选中 epoch、结果摘要和产物定位。交付时说明修改、实际验证及未验证项，不用“已修”概括所有状态。

## 7. 配置与集成

保留现有 `domain`、`summaryLanguage`、`recursive`、`chunkMessages`、`thresholdRatio`、`retainRatio`、`maxTokens` 参数，不臆改宿主 API，也不预设某组数值最优。

**一条已实测的硬下限**：`maxTokens` 必须 ≥32768。六节摘要比官方模板长得多，实测 8192 下压缩 **9/9 全部失败**（`summarization truncated at the token cap`，被 V4 正确拦下，但那段时间会话完全没有压缩）。这不是「宣布最优」，是低于它就不能工作的下限。**该下限在构造时强制**：未设置或低于下限即抛错，插件不启动——不把基础引擎的 8192 那个已知必坏的默认值放进运行时。其余参数仍按真实路由上限标定，不预设取值。

`summaryLanguage` 默认 `auto`，跟随用户的自然语言，避免被英文代码和日志带偏。额外提示只允许追加，不允许覆盖六节结构与保真约束。

按用户提供的部署信息，接入位置是在 `standard-pro` preset 的 `compaction` realm 中替换原后端，而不是另开 host 级压缩器。该部署情况仍须在实际工程中核实；本规范未访问或修改用户本机配置。

## 9. 定稿决定

六节和实验七字段保留；压缩模型不承担新的科研交叉推理；关键原文与当前执行契约同样保留；未决事项输出成问题包；记录“不改理由”、验证证据及未提交状态；未完成的关键计划不按时间简单淘汰；默认自动语言；仅做必要校验和少量针对性验证，不扩成平台。

定稿五条：**产品目标为研究连续性，但工作流模板不进入压缩引擎**（§0.1）；**跨会话连续性复用宿主的 `dsh-session-reference`，不另建快照格式**（§0.1）；**决定、已确定动作与已否决方案必须带 §2.7 的五个状态词之一，升级须写出依据**；**状态词只挂在 `[analysis]` 的 `decision:` 条目上，字段键用 ASCII，V1 只查格式不推断授权**（§2.4、§2.7）；**检查点按汇报视角写，`[goal]` 必带 `mainline:` 与 `progress:`**（§2.1）。检查项为四项。

**验收重点：下一位决策者能从摘要看清“确实记录了什么、尚不知道什么、需要决定什么”；下一位执行者能看清“按什么方案实现、哪些条件不能动、如何报告结果”；一个没有看过完整历史的新会话，能准确区分已确认方案与建议、已实现与已验证，并在不重新猜测科研定义的前提下完成下一项任务。**

**工作流验收**：用一个真实研究问题完成一次 `材料整理 → 强模型决策 → 小模型最小实现 → 记录结果 → 换会话继续`。只验证这一条闭环，不扩成大型评测工程。以 M1 为首个实例时，特别要看它是否保住：D5 为什么不改、R6 为什么不扩展、全部修改尚未提交，以及「报告已修」不等于旧实验产物仍然有效。
